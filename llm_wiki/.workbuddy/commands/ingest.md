# /ingest —— 摘录新内容并纳入知识库

> 前置：先读 `02-Schema/CLAUDE.md` §五（Processing 流水线）。本命令对应其完整流程。L1 不可变，你只读不写。

## 用法
```
/ingest <L1 资料路径，如 00-Raw-Sources/articles/2026-07-25-xxx.md>
```
若用户未给路径，先列出 `00-Raw-Sources/` 下尚未被摘要覆盖的资料，请用户指定。

## 标准流程
1. **确认 L1 落位（只读）**：读取指定原始资料，确认其已在 `00-Raw-Sources/`（articles/papers/data/images）下，不可变。记录标题、日期、核心论点与关键数据。
2. **写摘要**：在 `01-Wiki/50-摘要/` 新建 `{{date}}-{{标题}}-摘要.md`，
   - frontmatter：`type: summary`、`source: "[[../../00-Raw-Sources/...]]"`、填 `title/domain/tags/updated`。
   - 正文：5–8 条要点 + 关键数据；文末 `## 相关` 回链 L1 与将更新的 L2 页。
3. **级联更新（核心）**：通读摘要，找出所有相关概念/实体/对比/综述/索引页，**更新或新建**它们。一份新资料通常触发 **10–15 个页面**更新。例：新平台报道 → 更新 `[[Amazon 平台]]`、对应 `[[MOC-平台运营]]`、`[[平台运营综述]]`、相关对比页等。每页保持 frontmatter 规范与 `## 相关` 互链。
4. **矛盾标注**：若新数据与既有页冲突，在相关页插入：
   ```
   > [!warning] 数据冲突
   > 新源（日期）称 X，与本文此前的 Y 不一致，待核实。
   ```
5. **维护索引**：更新对应 `MOC-*` 与 `首页`，保证图谱连通、无孤立页。

## 收尾
向用户汇报：新增/更新了哪些页、是否发现冲突、MOC 是否已更新。不修改任何 L1 文件。
