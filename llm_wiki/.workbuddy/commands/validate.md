# /validate —— 校验矛盾知识 / 防腐

> 前置：先读 `02-Schema/CLAUDE.md` §五.4（矛盾标注规范）。本命令是其主动巡检版。

## 用法
```
/validate [可选：指定领域或实体，如 平台运营 / Amazon 平台]
```
不带参数则全库巡检。

## 标准流程
1. **扫描已标注冲突**：Grep 全库 `> [!warning] 数据冲突`，汇总所有已显式标注的矛盾，记录所在页、冲突双方表述、日期。
2. **主动比对（防腐核心）**：针对同一实体/概念页（尤其 `20-实体`、`10-概念`、`30-对比`、`40-综述`），
   - 比对数值（费率、佣金、时效、市场规模等）是否前后不一致；
   - 比对日期/版本（规则生效时间、政策更新）是否矛盾；
   - 比对结论（"X 平台适合新手" vs 另一页"X 门槛高"）是否相互打架。
3. **输出防腐报告**：
   ```
   ## 防腐报告（YYYY-MM-DD）
   - 已标注冲突：N 处（清单：页 → 冲突摘要 → 待核实动作）
   - 主动发现矛盾：M 处（清单同上）
   - 孤立/失联页：K 处（无 `## 相关` 或 wikilink 断链）
   - 建议：…
   ```
4. **可选追加标注**：经用户确认后，在相关 L2 页补 `> [!warning] 数据冲突` 标注，并在 MOC/首页提示待核实。

## 约束
- 只读分析 + 报告；**不擅自修改 L1**（L1 纠错只能建议库主追加新版本并在 L2 标冲突）。
- 不改写既有结论，只暴露矛盾并给出核实建议，把"裁决权"留给库主。
- 发现的规律（如某类平台数据频繁过期）可提议补充 `CLAUDE.md` 约定。
