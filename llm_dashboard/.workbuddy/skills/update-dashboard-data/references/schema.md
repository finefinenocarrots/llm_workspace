# 数据源表结构与处理口径

本文件记录 `scripts/process_data.py` 实际读取的 sheet 与列。**追加行时务必保持列名、sheet 名一致。**

---

## 一、广告数据看板源表
文件：`resource/关键词报告-每日明细.xlsx`

### Sheet: `sheet1`（逐日关键词明细 → 生成 kw_data.js）
脚本读取列（按顺序处理）：
| 列名 | 角色 | 说明 |
|------|------|------|
| 日期 | 维度 d | 取前 10 位字符串 `YYYY-MM-DD` |
| 运营负责人 | 维度 o | |
| 店铺名称 | 维度 s | |
| 国家 | 维度 c | 中文名，原样保留（前端做码映射展示） |
| 类目 | 维度 g | |
| 广告组合 | 维度 p | |
| 广告活动 | 维度 a | |
| 关键词 | 维度 k | |
| 匹配方式 | 维度 m | |
| 类型 | 维度 t | 取值 `SP`(Sponsored Products) / `SB`(Sponsored Brands)；2026-07-27 起数据源含 SB，行数约翻倍 |
| 曝光量 | 指标 im | 数值，缺失填 0 |
| 点击 | 指标 cl | 数值 |
| 花费-本币 | 指标 sp | 数值，**×汇率换算为美元** |
| 广告销售额-本币 | 指标 sa | 数值，**×汇率换算为美元** |
| 广告订单 | 指标 od | 数值 |
| 广告销量 | 指标 un | 数值 |

金额类本币列（参与汇率换算）：`CPC-本币`、`花费-本币`、`广告销售额-本币`、
`直接销售额-本币`、`CPA-本币`、`广告笔单价-本币`。

> **删除列的安全规则**：`process_data.py` 对以上「金额类本币列」做了 `if c in df.columns` 容错——
> 这些列中任意一列被删除，脚本会自动跳过、不会报错。其中只有 `花费-本币`、`广告销售额-本币`
> 会进入前端输出（kw_data 的 sp / sa），其余金额列仅参与换算而非必需。
> 因此删除「间接销售额-本币」这类**未被前端使用的可选金额列**是安全的。
> **但**以下列属于必需列，删除会导致 KeyError 中断，切勿移除：`日期`、`曝光量`、`点击`、
> `花费-本币`、`广告销售额-本币`、`广告订单`、`广告销量`，以及所有维度列
> （运营负责人/店铺名称/国家/类目/广告组合/广告活动/关键词/匹配方式/类型）。

### Sheet: `汇率`（汇率表，必须覆盖 sheet1 出现的全部国家）
| 列名 | 说明 |
|------|------|
| 国家 | 中文国家名，与 sheet1「国家」对齐 |
| 本币(=1) | 占位列，不参与计算 |
| 美元 | 汇率系数，usd = local × 美元 |

当前已知映射：DE/FR/IT/ES=1.176，UK=1.358，CA=0.73，US=1.0。

## 二、目标达成看板源表
文件：`resource/广告目标达成进度.xlsx`

### Sheet: `产品表现数据源`（日级实际 → tg_data.daily）
读取列：`日期, 负责人, 店铺, 国家, 类目, 销售额, 广告花费, 广告销售额, 展示, 点击, 广告订单量, 订单量`
- 日期格式化为 `YYYY-MM-DD`；仅保留 `日期 >= 2026-03-01`（更早行被丢弃）。
- `国家` 经 COUNTRY_MAP 映射为英文码：美国→US, 英国→UK, 德国→DE, 法国→FR,
  西班牙→ES, 意大利→IT, 加拿大→CA, 墨西哥→MX, 荷兰→NL, 波兰→PL, 瑞典→SE, 爱尔兰→IE。
- 按 `日期/负责人/店铺/国家/类目` 聚合出 sales, adsp, adsa, imp, clk, adod, od。

### Sheet: `每月销售目标`（月度目标 → tg_data.targets）
- 关键口径：**月目标花费取「本月目标月花费」**（不是「每月广告目标.本月目标花费」日级口径）。
- 目标 TACOS = 目标花费 ÷ 目标销售额。
- 与国家/SKU 通过 `list-info` sheet 的 `国家/公司SKU/店铺` 补全「店铺」列。
- 按 `年, 月份, 运营, 国家, 产品类目, 店铺` 聚合出 tgtSales、tgtSpend。

### Sheet: `list-info`
读取 `国家, 公司SKU, 店铺`，按 `国家+公司SKU` 去重，用于给「每月销售目标」补店铺。

## 三、生成产物字段速查
- `kw_data.js` → `window.KW_DATA`，行结构：
  `d,o,s,c,g,p,a,k,m,t, im, cl, sp, sa, od, un`（dims 为字典编码索引）。
- `tg_data.js` → `window.TG_DATA`：
  - `dailyCols: d,o,s,c,g, sales, adsp, adsa, imp, clk, adod, od`
  - `tgtCols: y, mo, o, s, c, g, ts, tp`（年, 月, 运营, 店铺, 国家, 类目, 目标销售额, 目标花费）
